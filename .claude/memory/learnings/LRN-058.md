# LRN-058 — Valider un algo aléatoire : N tirages sur données figées

**Pattern observé** : Fetcher l'API une seule fois (top tracks + épisodes), puis boucler 300 tirages en local en comparant ancien et nouveau code (min, p10, moyenne, nombre sous un seuil). Zéro appel réseau en plus, donc aucun risque de rate limit

**Contexte** : Validation du correctif de `buildMix` avant déploiement : 59/300 playlists sous 230 min avant, 0/300 après

**Application future** : Toute logique aléatoire ou dépendante de données réelles : prouver l'amélioration par distribution plutôt que par un seul run
