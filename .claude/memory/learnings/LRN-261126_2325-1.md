# LRN-261126_2325-1 — `deploy:edge --yes` refusé en mode auto même avec accord

**Pattern observé** : `pnpm deploy:edge` échoue d'abord avec `HostedMutationConsentRequiredError` (CLI Supabase 3.x en agent), puis `pnpm deploy:edge --yes` est refusé par le classifieur du mode auto (« Destructive or Unwanted Actions »), même après un accord explicite et ciblé de Baptiste (« Oui, déploie »). Le chemin « accord ciblé puis `--yes` » ne passe pas en mode auto

**Contexte** : Redéploiement de `generate-daily` après l'ajout du show Dbunk, le 2026-11-26. Baptiste a lancé la commande lui-même

**Application future** : Sur ce projet, en mode auto, ne pas tenter le déploiement : donner directement `pnpm deploy:edge --yes` à lancer. Vérifier ensuite avec `get_edge_function` (MCP Supabase) : sa sortie (~145 k caractères) est enregistrée dans un fichier, un `grep` de l'ID ajouté dans ce fichier suffit à confirmer que la version en ligne le contient. Voir aussi GLRN-342 et GLRN-261124_1515-1
