# LRN-073 — Symptôme intermittent : compter sur N jours avant d'expliquer

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| Une explication tirée d'un seul run se vérifie par un comptage sur plusieurs jours. Une requête `countIf(event_message like '%ignoré (429%')` sur `function_logs`, une fenêtre de 25 min par matin, donne la fréquence réelle en quelques secondes. Relire aussi le journal : une des occurrences y avait déjà sa cause | Le 09/10, 11 podcasts ignorés sur 429 chez le compte traité en second. Explication donnée d'abord : l'enchaînement des deux comptes entame le quota par app. Le comptage sur 5 matins (5, 0, 0, 0, 11) l'a contredite : trois matins sans 429 avec le même enchaînement, et les 5 du 05/10 venaient du blocage de la veille | Avant de présenter une cause pour un symptôme vu une fois, compter ses occurrences sur l'historique disponible. `query_logs` est limité à 24 h par appel : lancer une requête par jour en parallèle. Annoncer la taille de l'échantillon avec la conclusion |
