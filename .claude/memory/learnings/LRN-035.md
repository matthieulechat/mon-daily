# LRN-035 — Edge Function : un fichier lu sur disque n'est pas déployé

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| `uploadCoverImage` lisait `public/playlist-cover.jpg` avec `readFile`. Dans l'Edge Function, ce fichier n'existe pas (`NotFound … /var/tmp/sb-compile-edge-runtime/public/playlist-cover.jpg`) : seul le dossier de la fonction est déployé, et le CLI n'embarque que les modules importés | Le bug est resté dormant du 28/09 au 01/10 : la pochette n'est lue qu'à la **création** d'une playlist, chemin que le cron n'empruntait jamais tant que la playlist était trouvée. Il n'a éclaté qu'à cause de la recherche ratée du 01/10 | Dans une Edge Function, ne jamais lire de ressource par chemin : l'importer comme module (image en base64 dans un `.ts`, 43 Ko → 58 Ko). Ajouter un contrôle SHA-256 au boot (copie Edge uniquement) pour détecter une recopie corrompue. Tester les chemins rares (création) et pas seulement le chemin nominal |
