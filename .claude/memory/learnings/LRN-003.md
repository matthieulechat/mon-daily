# LRN-003 — Préférer `execFile()` à `exec()` par réflexe (hook sécurité)

| Pattern observé                                                                                                                                                                                                                                                              | Contexte                                                                                                                                    | Application future                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le hook de sécurité du projet flague tout `child_process.exec()` utilisé avec une string interpolée, même quand le contenu n'est pas une entrée utilisateur directe (ex. une URL OAuth construite en interne à partir du `client_id` et de paramètres générés côté serveur). | Fonction `openInBrowser()` du flow OAuth Spotify (`src/auth/login.ts`), qui ouvrait l'URL d'autorisation via `exec(\`start "" "${url}"\`)`. | Toujours écrire `execFile`/`spawn` avec un tableau d'arguments plutôt que `exec` + template string, par réflexe — même sur du contenu jugé "sûr" au moment de l'écriture, pour éviter la re-discussion à chaque fois. |
