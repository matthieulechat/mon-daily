# LRN-036 — `deploy_edge_function` MCP fragile sur gros fichiers : CLI

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| L'outil MCP `deploy_edge_function` exige que l'agent **recopie tous les fichiers** dans l'appel. Avec 14 fichiers dont un `cover-image.ts` de 58 Ko de base64, 3 tentatives ont échoué au bundling (fichiers omis, base64 tronqué) ; la version en production n'a jamais été touchée. `npx supabase functions deploy generate-daily --project-ref <ref>` lit directement le disque et passe en 2,4 s, après un `supabase login` fait une fois par l'utilisateur (OAuth navigateur, non automatisable) | Déploiement de la v7 de `generate-daily` le 2026-10-01. Complète [LRN-032](../learnings/LRN-032.md) qui recommandait le MCP faute de login CLI : valable pour de petits fichiers seulement | Fichiers volumineux ou nombreux : demander à l'utilisateur de faire `npx supabase login`, puis lancer le déploiement CLI. Réserver le MCP aux petites fonctions. Après déploiement : `list_edge_functions` (version, `verify_jwt`) puis rejouer le cron ([LRN-025](../learnings/LRN-025.md)) et lire les logs |
