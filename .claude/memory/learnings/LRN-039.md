# LRN-039 — RLS Supabase : `auth.identities`, pas `user_metadata`

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| Une policy RLS qui lit `auth.jwt() -> 'user_metadata'` est exploitable : l'utilisateur modifie son `user_metadata`. L'id du provider se lit dans `auth.identities` via une fonction `security definer` placée dans un schéma `private` (`set search_path = ''`, `revoke` à `public`/`anon`) | Première version de `user_settings` avec `user_metadata ->> 'provider_id'` : `get_advisors` a remonté `rls_references_user_metadata` (ERROR), corrigé par `private.current_spotify_id()` | Lancer `get_advisors` (security) après toute migration RLS ; ne jamais baser une policy sur `user_metadata`, utiliser `auth.uid()` ou `auth.identities` |
