# LRN-046 — Ne jamais lancer un gros lot de requêtes Spotify sans plafond ni arrêt au 429

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| ~2 000 requêtes de recherche/épisodes en rafale avec les identifiants de l'app (client credentials) → 429 avec `Retry-After` ≈ 82 000 s (~23 h). Le script, qui respectait docilement le délai, est resté suspendu des dizaines de minutes sans rien afficher ; un run `pnpm generate` lancé ensuite a lui aussi pendu | Recherche de nouvelles sources podcast (régional, international, radios, presse) pour la section thématique/actu | Plafonner à ~30 requêtes par session, ≥ 1 s d'écart, journaliser la progression ; **abandonner dès le premier 429 avec un `Retry-After` long** (> 60 s) au lieu d'attendre ; sauvegarder les résultats au fil de l'eau ; prévenir l'utilisateur avant un lot > 50 requêtes. Ne pas relancer `pnpm generate` pour « tester » pendant un blocage |
