# LRN-034 — Runs de test répétés : 429 Spotify, pool d'actu dégradé

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| Chaque run tire ~90 appels `/shows/.../episodes` en rafale ; après plusieurs runs rapprochés, Spotify répond 429 avec `Retry-After` ≈ 779 s (limite par app, pas par compte). `fetchSpotifyWithRetry` attend ce délai (le run « bloque » 13 min) puis, après 3 essais, `getEligibleEpisodes` log « ignoré (429) » et le show contribue 0 épisode : le pool d'actu est tombé de 8 à 1 sans erreur visible | Tests locaux successifs de `pnpm generate` sur 2 comptes le 2026-10-01. Mon `grep -v "ignoré"` masquait justement les lignes « ignoré (429) », ce qui a fait croire à un bug de sélection | Espacer les runs de test de plusieurs minutes ; ne jamais filtrer les lignes « ignoré » en lisant la sortie d'un run ; sonder l'état du rate limit avec une seule requête (`/shows/<id>/episodes`) avant de relancer. Un pool d'actu anormalement bas = vérifier d'abord les 429 |
