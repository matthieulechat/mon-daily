# LRN-012 — Colonne dupliquée = souvent une identité interne/externe pas encore séparée

| Pattern observé                                                                                                                                                                                                                                                                                                                                                                                                                                              | Contexte                                                                                                                                                                                                                                                                                                                                         | Application future                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sur `users` (mon-daily), `id` et `platform_user_id` contenaient toujours la même valeur — un `SELECT` a confirmé le doublon sur 100% des lignes. Ce n'était pas du bruit accidentel : `platform_user_id` existait pour porter un identifiant externe (Spotify) distinct d'un futur identifiant interne, mais le code (`supabase-storage.ts`) copiait bêtement l'un dans l'autre faute d'avoir jamais eu besoin de les différencier (un seul provider actif). | Question posée par Baptiste en lisant le schéma : "id et platform_user_id ont la même valeur, doublon ou colonne inutile ?" — creuser la question a mené à découvrir que le vrai problème n'était pas la colonne en elle-même mais l'absence de séparation identité/compte externe dans tout le modèle (cf. [BDR-010](../decisions/BDR-010.md)). | Avant de conclure "colonne inutile, à supprimer" face à un doublon de valeurs, vérifier si la colonne porte une distinction _intentionnelle_ (identité interne vs identifiant externe, ex. OAuth/SSO/multi-tenant) qui n'est simplement pas encore exploitée par le code — le doublon peut être le symptôme d'un modèle de données incomplet plutôt qu'une redondance à nettoyer. |
