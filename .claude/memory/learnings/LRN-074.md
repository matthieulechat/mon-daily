# LRN-074 — Login OAuth en panne : valider chaque saut sans se connecter

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| Un parcours OAuth se vérifie saut par saut sans saisir d'identifiants : page chargée et console vide, variables d'env du bundle (le bouton part vers le bon projet Supabase), `redirectTo` dans le code, puis `redirect_uri` lu dans l'URL de la page de connexion du fournisseur. Ce qui reste non vérifié désigne le saut fautif | Connexion en échec sur `mon-daily.vercel.app`. Les quatre premiers sauts étaient bons, il ne restait que le retour Supabase vers l'app. Deux impasses : le `state` GoTrue est maintenant opaque (plus un JWT dont on décode le `referrer`), et la configuration d'URL de Supabase Auth n'est pas lisible via le MCP Supabase | Avant de supposer, dérouler les sauts dans le navigateur intégré jusqu'à la page de connexion du fournisseur, sans s'authentifier. Ne pas perdre de temps à décoder le `state`. Pour la configuration d'URL, donner à l'utilisateur le lien direct du dashboard et lui demander où il atterrit après connexion |
