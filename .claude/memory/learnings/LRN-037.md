# LRN-037 — `tsx` hors projet sous Windows : `.mts` + imports `file:///`

| Pattern observé | Contexte | Application future |
| --------------- | -------- | ------------------ |
| Un script jetable placé dans le scratchpad (sans `package.json`) est compilé en CJS : `Top-level await is currently not supported with the "cjs" output format`. Renommé en `.mts`, les imports par chemin absolu `C:/…` échouent en ESM (`Received protocol 'c:'`) ; il faut `file:///C:/…/src/x.ts`. Lancé avec `pnpm exec tsx <chemin>` depuis la racine du projet, il réutilise le code du projet (refresh de token et stockage identiques à la prod) | Diagnostic Spotify du 2026-10-01 : lister les playlists, vérifier la visibilité, tester le rate limit, sans exposer les tokens ni écrire dans le repo (`pg_net` ne convenait pas : il n'envoie que du JSON alors que le endpoint token Spotify exige du form-urlencoded) | Pour un script de diagnostic jetable : `.mts` dans le scratchpad, imports du projet en `file:///`, aucune écriture dans le repo. Ne pas afficher de token (le script ne logue que des statuts, noms et ids) |
