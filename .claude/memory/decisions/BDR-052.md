# BDR-052 — Suivi de santé des sources podcast

**Décision** : Table `show_health` partagée entre comptes (une ligne par show) et vue `dead_shows`. Vérification passive pendant la génération (callback `onShowChecked`, date du dernier épisode exploitable après filtres de titre), puis rotation de 10 shows/jour non interrogés (optIn compris) avec le token app, 1,2 s d'écart, arrêt au premier 429. Mort = dernier épisode de plus de 30 jours (ou aucun exploitable) ou 404. Alerte sur un second push monitor Kuma « Mon Daily — sources » (`UPTIME_SOURCES_PUSH_URL`), rappel tous les 7 beats

**Pourquoi** : Zéro requête en plus pour les shows actifs, couverture complète du pool en ~5 jours très loin du rate limit ([LRN-046](../learnings/LRN-046.md)), et une panne de génération jamais masquée par une source morte (voir aussi GLRN-353). Premier run : 5 morts détectés, 3 retirés

**Alternatives considérées** : Vérifier les ~170 shows chaque jour (trop d'appels) ; seuil de 7 jours (fausses alertes sur pauses estivales et hebdos) ; même monitor que la génération (pannes masquées) ; ne pas surveiller les optIn (leur mort passerait inaperçue)
