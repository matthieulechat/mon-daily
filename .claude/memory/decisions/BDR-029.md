# BDR-029 — Id de playlist stocké par compte, plus de recherche par nom

| Décision | Pourquoi | Alternatives considérées | Statut |
| -------- | -------- | ------------------------ | ------ |
| Stocker l'id de la playlist « Mon Daily » dans `oauth_tokens.playlist_id` (colonne nullable, une par compte) ; `createOrUpdatePlaylist` accepte `knownPlaylistId` et renvoie l'id, `generate.ts` / `generate-playlist.ts` le lisent et le sauvegardent s'il change. La recherche par nom ne sert plus qu'à l'initialisation | Le 2026-10-01 à 05:00 UTC, `/me/playlists` n'a pas renvoyé « Mon Daily » pour les 2 comptes alors qu'elle existait : le code a recréé une playlist vide en doublon puis planté sur la pochette. Cause de la recherche ratée non prouvée → l'id supprime la dépendance à la recherche, quelle qu'en soit la cause | Paginer `/me/playlists` (les comptes ont 35 et 14 playlists, pas un problème de pagination) ; supprimer seulement les doublons (ne prévient pas la récidive) ; contrôler l'existence de l'id à chaque run (un appel de plus, marqué `ponytail:` dans le code) | actif |
