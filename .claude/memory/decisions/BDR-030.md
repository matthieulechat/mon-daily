# BDR-030 — UI de réglages : SPA Vite + Supabase Auth Spotify, RLS

| Décision | Pourquoi | Alternatives considérées | Statut |
| -------- | -------- | ------------------------ | ------ |
| Interface `web/` (Vite + React + Tailwind 4, direction « Bulletin Groove » de BDR-004) : login via Supabase Auth (provider Spotify), réglages dans la table `user_settings` (clé `platform` + `platform_user_id`, durée max 60-480 min, `disabled_show_ids`). RLS : policies `authenticated` qui comparent `platform_user_id` à `private.current_spotify_id()` (fonction `security definer` lisant `auth.identities`). Le script et l'Edge Function lisent la ligne via `Storage.getSettings` (défauts = ancien comportement) | Le job quotidien doit lire des préférences par utilisateur sans redéployer le code à chaque changement ; l'identité Spotify relie le compte Auth au compte `oauth_tokens` | Next.js (plus lourd pour une page) ; page HTML statique (peu évolutive, 55 shows) ; pas d'auth avec clé en dur (non sécurisé, pas multi-utilisateur) | actif |
