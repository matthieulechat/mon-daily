# BDR-045 — Génération à 7h Paris : cron `0 5,6` + filtre SQL

| Décision | Pourquoi | Alternatives considérées | Statut |
| -------- | -------- | ------------------------ | ------ |
| Le job `generate-daily` est planifié sur `0 5,6 * * *` (UTC) et sa commande se termine par `where extract(hour from now() at time zone 'Europe/Paris') = 7` : un seul des deux passages appelle l'Edge Function | Matthieu veut une génération à 7h heure de Paris toute l'année ; `pg_cron` ne connaît que l'UTC, donc `0 5 * * *` glissait à 6h en hiver. Le filtre SQL ne demande aucun redéploiement et n'invoque la fonction qu'une fois par jour | Garde horaire dans l'Edge Function (redéploiement, deux invocations par jour) ; décaler le cron à la main deux fois par an (oubli garanti) ; garder l'heure « tolérante » 6h/7h (refusé) | actif |
