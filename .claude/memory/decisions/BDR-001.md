# BDR-001 — Migration en 2 étapes JSON local → Supabase

**Décision** : Étape A : script lancé manuellement, stockage dans `data/store.json` (fichier local, `fs/promises`). Étape B : bascule vers Supabase (Postgres + Vault pour les tokens) avec automatisation via `pg_cron`. Les deux étapes partagent la même interface `storage.interface.ts` pour que la migration ne touche que la couche de stockage, jamais la logique métier.

**Pourquoi** : Valider le concept rapidement sans infra ni coûts avant d'investir dans l'automatisation. Le stockage JSON local suffit pour un usage perso (V1) le temps de prouver que le mix musique/podcast fonctionne.

**Alternatives considérées** : SQLite dès le départ (rejeté : complexité inutile pour un seul utilisateur en V1) ; Supabase dès le départ (rejeté : setup infra prématuré avant validation du concept).
