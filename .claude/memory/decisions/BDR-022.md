# BDR-022 — Vault sécurise l'appel `pg_cron`, pas les tokens OAuth

| Décision                                                                                                                                                                                                                                                                                   | Pourquoi                                                                                                                                                                                                                                                                 | Alternatives considérées                                                                                                                                         | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Supabase Vault stocke uniquement la clé `service_role` (`generate_daily_key`) utilisée par `pg_cron` pour authentifier son appel HTTP vers l'Edge Function. Les tokens OAuth Spotify des utilisateurs restent dans `oauth_tokens`, déjà protégée par RLS (accès uniquement `service_role`) | Corrige une hypothèse écrite dans `docs/AUTOMATION.md`/ROADMAP ("migrer les tokens vers Supabase Vault") : en relisant la doc Supabase au moment d'implémenter, Vault sert à sécuriser le _déclencheur_ du cron, pas les credentials applicatifs déjà protégés autrement | Migrer aussi les tokens OAuth vers Vault — écarté, aucun gain de sécurité (RLS + accès service_role uniquement déjà en place) pour une complexité supplémentaire | actif  |
